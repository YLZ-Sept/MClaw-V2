# 授权码签发操作说明

给客户签发 MClaw 授权码。全程离线，不需要联网。

## 开始之前

你需要两样东西：

1. **签发页面** —— `index.html`（就是这个文件夹里的）
2. **签发私钥** —— `private.pem`

用 **Chrome、Edge 或 Firefox** 打开 `index.html`（双击即可）。不需要联网。

> **私钥就是签发权。** 谁拿到这个文件谁就能签出授权码，而且软件是离线校验的，
> 签出去的码在有效期内**收不回来**。请勿转发、勿放共享盘、勿传微信。

## 签发四步

### 1. 加载私钥

点「选择文件」选中 `private.pem`，显示 `✓ 私钥已加载` 即可。

每次重新打开页面都要选一次 —— 页面不保存私钥，这是有意的。

### 2. 填信息

| 填什么 | 说明 |
|---|---|
| **客户名称** | 填正式公司名，客户激活成功后屏幕上会显示这个名字 |
| **客户机器码** | 客户发给你的那串码，形如 `2F72-4463-9B50-7666-617F` |
| **有效期** | 下拉选，或选「指定到期日」自己挑日期 |
| **用户数上限** | 客户最多能建几个账号，填 `0` 表示不限 |
| **档位备注** | 选填，比如"标准版"，只是备注 |
| **开放功能** | 不勾的功能客户用不了。拿不准就全勾 |
| **流水号** | 留空自动生成，不用管 |

机器码粘进去会立刻校验，绿色 `✓` 才能往下走。

### 3. 生成

点「生成授权码」，下面会出现客户名、有效期、用户数的确认信息，**核对一遍**，
然后点「复制授权码」。

### 4. 发给客户

把复制到的那串 `MC1.` 开头的码发给客户，客户粘贴到激活页点激活就好了。

---

## 客户的机器码从哪来

客户装好软件、设完密码、登录之后，会看到激活页面，上面有「本机机器码」和一个
「复制」按钮。让客户点复制发给你就行。

---

## 三件必须知道的事

### 一码只能激活一台机器

机器码是客户电脑的硬件指纹。签给 A 电脑的码，B 电脑用不了。

客户**换电脑、重装系统、换硬盘主板**都可能让码失效 —— 这时让客户重新发一次
新机器码，你重新签一个给他。旧码作废，不用回收。

### 发出去就收不回

软件不联网校验，所以码一旦发出，在有效期内你**没有任何办法让它失效**。

所以：**新客户、试用客户先签 1 个月**，确认付款后再签长期的。

### 台账要定期导出

签发记录存在你这台电脑的浏览器里。清缓存、换电脑、甚至浏览器自动清理都可能丢。

**每次签完顺手点一下「导出 CSV」**，存到公司网盘。里面有完整的授权码原文，
客户说码弄丢了，从这里翻出来重发就行，不用重签。

换电脑时用「导入 CSV」把记录恢复回来。

## 遇到问题

**「机器码仅 N 段可用」**
客户电脑的硬件信息读不全（常见于虚拟机）。这种码签了也激活不了，
让客户联系技术支持。

**「当前浏览器不支持 Ed25519」**
不影响使用。页面会自动改用内置算法，签出的码完全一样，正常往下走即可。

**「不是 PKCS#8 私钥文件」**
选错文件了。要选 `private.pem`，不是公钥或其他文件。

**客户说激活报错「授权码与本机不匹配」**
客户发的机器码和实际激活的机器不是同一台，或者中间换过硬件。
让客户在激活页重新复制一次机器码发来。

## 给技术人员

浏览器端签发逻辑与 `tools/license_gen.py` 逐字节等价，同输入产出同一个码
（Ed25519 是确定性签名）。改动 `index.html` 中的 `serializePayload`、
`b64url`、`pyRound` 之后**必须**重跑一致性校验：

```bash
python tools/license_web/gen_expected.py     # 由 Python 端生成基准
node   tools/license_web/verify_parity.mjs   # 比对浏览器端实现
node   tools/license_web/verify_noble.mjs    # 纯 JS 回退路径与原生一致
node   tools/license_web/sign_e2e.mjs        # 端到端：签码 → 产品端验签
```

签名有两条路径：优先 WebCrypto 原生 Ed25519，失败时自动退到内联的
`@noble/ed25519`（纯 JS，只依赖通用的 SHA-512 摘要）。部分浏览器即使版本足够新，
`importKey({name:"Ed25519"})` 仍会抛 `Unrecognized name`——企业策略、内核变体
都可能触发，所以回退路径是必需的而非可选。两条路径产出逐字节相同的码。

升级 vendor 库或改动页面模板后，必须重跑 `python tools/license_web/build.py`
把库重新内联进 `index.html`（`file://` 下浏览器拒绝加载 ES module，必须内联）。

命令行签发仍然可用，两条路径可混用（台账格式相同，可互相导入）：

```bash
python tools/license_gen.py --cust "某公司" --fp XXXX-XXXX-XXXX-XXXX-XXXX --months 6 --users 20
```
